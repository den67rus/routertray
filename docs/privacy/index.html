Information used and why

RouterTray reads Windows network names and identifiers, network adapter identifiers, MAC addresses, and gateway addresses to identify the selected computer and choose its router profile. You supply router addresses, profile names, and a router username and password or an access token. The application uses these details to authenticate with the router you configure.

Router responses provide policy names, current assignments, and device names, MAC addresses, and registration details. A response may contain information about other devices on that router; RouterTray uses it to find the selected device. Selecting a policy sends that device's MAC address and the selected policy to the router. If you explicitly register a device during setup, the application sends its MAC address and your chosen device name and may ask the router to save its configuration.

The application has no developer-operated backend, advertising or analytics SDK, and does not automatically upload settings, credentials, or diagnostic logs to the developer. It does not inspect browsing history or the contents of your internet traffic. Local router operations do not send those details to the developer.

Router connections and external services

Router requests use the address you configure or the detected gateway and the router's authentication endpoints. This is normally a local network connection, but a manually entered address can point elsewhere. The owner of that endpoint receives the requests. Choose only a router you are authorized to manage.

Connections use HTTP or HTTPS according to the configured address. HTTPS uses Windows certificate validation. HTTP does not encrypt the transport: someone able to observe the connection may read authentication tokens, identifiers, commands, and responses. Prefer a trusted HTTPS endpoint where supported, and do not use HTTP over an untrusted network. No software or encryption mechanism can guarantee protection against every attack or compromise.

Microsoft Store builds receive application updates through Microsoft Store and do not check GitHub Releases. Other installed builds can contact GitHub to check for and download updates, according to their update settings. Microsoft, GitHub, email providers, your router, and other services you choose may receive ordinary connection information, such as IP addresses, and process information under their own terms and privacy notices. Those services may process information in countries different from yours. Opening an external link or contacting support uses the service you choose.

Local storage, security, and retention

Profiles and preferences are stored in the current Windows user's local application data. Saved passwords and access tokens are protected with Windows Data Protection API (DPAPI), scoped to that Windows account. Profile names, router addresses, usernames, network bindings, and other preferences are ordinary settings and are not all encrypted. Secrets must also be available to the application in memory while authenticating.

DPAPI is not protection against every threat, including malware running as the same Windows user, a compromised Windows account, or a compromised computer. You control Windows account access, router permissions, backups, and the endpoints you configure. The developer cannot remotely access or erase files that remain only on your computer.

Diagnostic logs remain on the computer. They can contain timestamps, network, adapter, profile and policy identifiers, errors, and details returned by the router. Logs are not a secure vault, and unexpected router responses may contain sensitive information. Review and redact logs before sharing them.

Settings, backup copies, logs, and preserved corrupt settings files can remain until you or Windows remove them. Removing a profile does not necessarily remove older copies. Uninstalling the application does not guarantee deletion of every backup, exported file, router-side record, or third-party copy.

Your choices and deletion

You can edit or remove profiles, choose startup behavior, and change policy notifications in Settings. Other installed builds also offer update settings; Microsoft Store updates are controlled by Windows and Microsoft Store.

Exit RouterTray before manually deleting local settings, logs, and backups. The usual unpackaged folder is %LOCALAPPDATA%\RouterTray. Windows may redirect Store files into the application's per-user package storage under %LOCALAPPDATA%\Packages. Revoke router tokens or accounts in the router's own administration interface: deleting a local profile does not revoke them. Router configuration and registration records must be managed on the router.
